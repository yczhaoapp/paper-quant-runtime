# 四轴证据口径

题目评审的是运行契约、可执行样例、结构化故障、兼容审计、测试、沙箱和报告。以下 A/D/R/E 是**本仓库内部的证据语言**，不是主办方等级或额外的 S 档硬指标。任何一轴的等级都不能自动提高另一轴。逐策略人工审阅记录位于 `research/assurance-axes.json`，原文主张和独立 oracle 另有固定哈希。

| 轴 | 内部等级 | 判定边界 |
| --- | --- | --- |
| A：论文方法 | `A0` 适配演示；`A1` 缩减但等价的方法；`A2` 指定范围内的精确公式或更新 | 每例分别评定**已验证核心**和**完整交易方法**。核心公式 A2 不表示原论文的动作、奖励、行情模拟器或实验结果均被恢复。 |
| D：行情数据 | `D0` 明示合成夹具；`D1` 固定公开代理数据；`D2` 等价原论文市场；`D3` 原论文样本 | D1 要求实际公开数据运行、原始来源字节、输入哈希，以及训练型案例的时间谱系。D1 不暗示 D2 或 D3。 |
| E：论文结果 | `E0` 仅运行结果；`E1` 可比数据上的方向性结论；`E2` 主要表格和统计结果 | E1/E2 需要原论文市场、成本、切分、基准、随机种子、指标及预先声明的容差；当前没有此类主张。 |
| R：执行证据 | `R1` 主机论文接入运行；`R2` 隔离严格 worker 运行 | R 只能由**本轮成功收据**授予，不写入静态策略矩阵。论文深度验收的 R1 覆盖 18 个目录论文运行和 1 个独立新论文；严格验收的 R2 覆盖 18 个目录策略的运行时。这是两个不同范围。 |

当前核心审阅判断为 13 个 A2、5 个 A1；完整交易方法为 8 个 A1、10 个 A0，**没有完整方法被宣称 A2**。这些是人对复现范围的判断，不是 JSON 标签自行证明的事实。验收会把判断绑定到未改动的论文主张、具体实现和非空 oracle 节点，并实际运行 oracle；机器检查仍不能替代语义审阅。例如 Double Q 的双表更新来自独立算法原文，核心为 A2；报价动作、tile coding、奖励和交易所模拟器发生变化，所以完整做市方法仍为 A0。

八个目录策略有 D1 公开代理行情运行：规则 3 个、监督 4 个、强化学习 1 个。八者使用**同一份**固定 AAPL CSV，代表八条方法运行轨，而非八个独立市场。其余十个策略用 D0 夹具。独立 Busseti–Boyd 案例对经审阅的静态公式为 A2，对完整执行策略为 A0，示例分钟线为 D0，论文实验结果为 E0；只有论文深度尝试成功时才得到 R1。目录中的 18 个策略全部为 E0。

`scripts/assurance_axes.py` 检查矩阵结构及其主张和 oracle 绑定。`scripts.accept_paper_depth` 固定矩阵 SHA-256，运行全部目录论文案例和独立新论文，发布八条公开数据 `paper-run` 记录及 R1 收据。`scripts/verify_strict.py` 仅在干净提交的 18 项严格隔离验收通过后发布 R2。失败或过期收据不授予 R 等级。完整论文深度门禁目前在主机执行，因为未获再分发授权的 PDF 需显式获取到本地缓存；严格运行时门禁使用独立容器 worker。

分级不改变题目的 18 个策略计数，也不把它写成 18 篇不同的主论文。目录对应 16 篇不同主论文，Double Q 另有一篇算法原文，此外有一篇独立新论文。各案例的具体方法和数据偏差仍以 `research/claims/` 与 `research/deep-specs/` 为准。
