# 运行契约草案

## 输入和生命周期

策略目录声明类别、时间粒度、字段、标的、训练要求和允许动作。数据集另行声明同样的属性，并提供带事件时间与可用时间的实际行情。编译器先检查版本、字段、粒度、标的、动作和引擎能力，再生成不可变运行计划。计划固定引擎能力及执行配置的快照与哈希；改变初始现金或手续费会改变执行配置哈希。直接调用参考引擎也核对实际配置。

bar 数据还必须声明 `bar_open_time`。`event_time` 是该 bar 收盘、OHLCV 已形成的时刻，`available_time` 是策略可读取它的时刻。未声明精确时长的旧式分钟数据只接受时长大于零且不超过 60 秒的 bar；5 分钟等新输入必须在数据集声明 `bar_seconds`，每根 bar 的实际时长须与声明完全一致，策略也可声明同一时长，编译器拒绝不匹配。日线数据集必须声明 `session_timezone`、`session_open` 和 `session_close`，每个标的每个当地交易日只接受一个符合该时段的 bar，并要求时段长 1 至 24 小时。休市日可以没有 bar；合法半日交易须使用独立、明确的会话数据集。分钟聚合日线须在政策中显式指定目标开闭市时刻，转换后仍通过同一会话检查。日期型源数据的交易时钟属于数据适配假设，应在来源记录中说明。

数据集可声明 `market_kind=bar|trade|quote_l1|book_l2`；已有单流数据未声明时，由粒度和字段确定类型。编译器逐事件验证正数价格、OHLC 区间、非负成交量、双边报价、严格未交叉的最优买卖价，以及 L2 连续档位、买盘降序、卖盘升序和正数档位数量。显式成交流还要求 `trade_id`、正数 `trade_size`，可标记 `aggressor_side`；只给最优买卖价的旧报价流仍可使用，但显式声明的 L1 订单簿必须同时给出双边数量。策略可声明 `minimum_book_depth` 和 `max_staleness_seconds`；深度不足或 `available_time - event_time` 超限均结构化失败。当前输入仍是单一流的扁平 `values`，上述类型约束明确解释其字段；不同类型的混合多流暂不声明为已支持。

参考引擎只在目标标的下一条开盘不早于订单接受时间的事件上撮合；同刻异步标的的已过去开盘价不能用于后来产生的信号。bar 成交记在所用 bar 的 `bar_open_time`，策略此时尚不能读取该 bar 的收盘值。编译器拒绝开盘时间早于同一标的前一条信号可用时间的数据；报告核查成交时间不早于接受时间。tick 无 `bar_open_time`，按事件可用时间撮合。

运行顺序为校验输入、训练、写入制品、退出训练实例、在全新实例中加载制品、逐事件推理、因果合格的后续事件撮合和生成报告。严格模式会销毁训练容器，再启动独立推理容器。规则型策略可声明无需训练，监督与强化学习策略必须提供训练请求。`replay-bundle` 可从已保存的制品直接冷启动推理，不重新训练。

直接使用开发模式的 Python `run()` 时，学习策略默认通过无参构造器创建推理实例；有构造参数的外部策略应显式传入 `strategy_factory`。目录包入口依据已核验的清单自动构造新实例。无法新建或无法仅凭制品恢复时，运行明确失败。

训练样本对监督任务提供 `features` 与 `target`；对强化学习任务提供 `features`、`action`、`reward`、`next_features`、`next_action` 和 `terminal`。新 RL 输入可另声明 `episode_id`、从零连续递增的 `step` 与 `truncated`，此时每个 episode 必须显式终止或截断，不能混合有边界与无边界的样本。旧样本不被臆造 episode；终止与截断同时为真会被拒绝。`truncated` 不替算法决定是否 bootstrap，策略仍负责验证其更新公式、特征和相邻动作关系。训练请求整体哈希写入计划及模型产物，运行时在训练后再次核对；对恶意策略的完整输入隔离仍须由严格 worker 验证。

## 账户和动作

账户快照含现金、权益、净持仓、持仓均价、累计已实现毛价格损益、按当前可用价格计算的未实现损益，以及等待下一次撮合的订单 ID。手续费单独记录在成交与现金中；订单状态在报告的 `OrderEvent` 轨迹中逐项记录。策略可返回不交易、预测、目标持仓或新订单；动作必须在声明与引擎能力交集中。当前策略账户输入只暴露挂单 ID，不提供完整挂单价量明细，因而不能把它宣称为完整订单簿做市账户接口。

`RunPolicy.financing_mode` 固定资金假设并进入运行计划和报告。默认 `cash_only`：若下一事件成交价加手续费会使现金为负，订单以 `ORDER_REJECTED` 明确失败。`unbounded_margin` 仅是研究模拟中的显式无限授信假设，不计算借贷利息、保证金、强平或借券成本；不得据此声称真实券商可执行。参考引擎目前允许卖空并假定可借券，仍不模拟借券费或强平。配对 A2C 的合成双腿样例明确选择 `unbounded_margin`，因此其权益轨迹必须连同该政策解读。

`submit_order` 默认在目标标的下一条因果合格事件上执行市价单；设置正数 `limit_price` 后只在该事件有效。tick 买单只有在最优卖价不高于限价时按该卖价成交，卖单只有在最优买价不低于限价时按该买价成交；缺少或无效的最优报价明确失败。bar 限价单只依据该根开盘价判断与成交，不使用尚未形成的最高价或最低价。该次事件不可成交时记录 `expired`，回放在订单等待期间结束也记录 `expired`。当前参考引擎不模拟跨事件排队、部分成交或撤改单，因此不能把它用于声称真实订单簿做市撮合结果。

## 错误与兼容

策略收到隔离的行情与账户副本；主机和严格 worker 都从动作的 wire 字段重新验证，不能用未经校验的 `model_copy` 值绕过方向与数量约束。`bundle.json` 包含声明、实际输入、源码与模型附件；离线校验同时核查计划哈希、转换链和成交时间。

字段缺失、时间粒度不匹配、标的映射失败、非法动作或订单、模型缺失、训练和回测失败均使用稳定错误码和阶段、输入引用、详情及不可回退标记。外部引擎抛出的非契约异常在运行时边界转为 `BACKTEST_FAILED`，CLI 写入本轮失败收据。目标持仓在下一事件转换为实际订单后同样受单笔数量限制。标的映射和 bar 聚合必须由运行政策显式授权；每条转换记录包含原因、授权开关、能否关闭、输入输出事件数、受影响源标的、参数及前后数据哈希，并随计划写入报告。迟到 bar 若会打乱同标的市场时间顺序则明确拒绝。

## 扩展与隔离

引擎适配器只实现数据喂入、撮合、账户和成交语义，训练与模型制品由运行时完成。可执行的引擎协议、能力绑定与第三方接入条件见[引擎扩展边界](engine-extension.md)。当前可执行策略包是受限的单文件 `strategy.py`，清单与该文件通过 SHA-256 绑定；包内 helper 模块、自选 NumPy/PyTorch 依赖及在线安装均不在当前受信画像内。需要这些依赖的新实现应先建立锁定环境与整个代码树的身份，再扩展沙箱与验收，不能通过放宽扫描器暗中接入。来源和论文主张由研究记录核查；项目目前不提供数字签名、签名人身份认证或可信发布者证明。严格模式将策略代码放入受限容器，并核查实际网络、文件系统、用户和资源限制。进程内扫描仅作为提前拒绝机制。
